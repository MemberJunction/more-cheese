# metadata/ — intentionally empty of seed data

**The demo seed is NOT shipped as mj-sync metadata.** It ships as **compact multi-row `INSERT`
data migrations** in `migrations/` (generated by `datagen/cli/emit-sql.mjs`). Metadata-as-migration
via `mj sync push` + `sqlLogging` was abandoned: at ~96k records it produces a ~100–240 MB
per-record migration that exceeds GitHub's 100 MB blob-fetch ceiling the Open App install path
relies on.

So this folder ships **no entity/data records** and `directoryOrder` is empty — nothing here is
pushed at install or dev-link (deliberate: an accidental `mj sync push` of a 96k-record tree must
be impossible).

## Still available for dev/review (on demand, not committed)
The mj-sync tree is regenerable any time from the datagen packs:

```sh
npm run datagen:build      # generate the universe → out/packs
npm run datagen:emit       # emit the mj-sync tree (--metadata-out) for inspection / dev push
```

Use that when you want the human-readable, diffable metadata form (or to `mj sync push` into a dev
DB for inspection) — but do **not** commit the emitted tree. The committed, shippable artifact is
the data migrations.
